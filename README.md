# Треклист для slskd

Веб-приложение принимает по одному поисковому запросу на строку, выполняет ограниченное число поисков одновременно, выбирает аудиофайл из ответов Soulseek и ставит его в очередь загрузок slskd. Если первый поиск ничего подходящего не нашёл, приложение может повторить его с более длинным таймаутом.

## Запуск через Docker Compose

1. Скопируйте `.env.example` в `.env` и укажите адрес slskd и API-ключ.
2. Подключите сервис к той же Docker-сети, что и slskd. Если slskd работает отдельно, задайте доступный из контейнера адрес, например `http://host.docker.internal:5030`.
3. Запустите `docker compose up -d --build`.
4. Откройте `http://localhost:8090`.

В slskd создайте API-ключ с правами на поиск и управление загрузками. Порт API (обычно `5030`) должен быть доступен из контейнера. Можно также настроить URL и ключ в окне шестерёнки приложения; настройки хранятся в именованном Docker volume `soulseek_queue_data`.

## Настройки

- Длительность первого поиска: 2–600 секунд.
- Одновременные поиски: 1–32.
- Опция ускорения первых поисков: первые пять треков списка запускаются с лимитом 5, если обычный лимит не выше 5; затем действует заданный лимит.
- Порог совпадения первого поиска: 10–90% (по умолчанию 25%); у повтора отдельный порог (по умолчанию 15%).
- Повторный поиск ненайденных треков: включается отдельно, с длительностью 5–1800 секунд.

Таймаут `searchTimeout` передаётся slskd в миллисекундах. Для списка допускается до 500 строк за отправку; записи очереди сохраняются в SQLite и остаются после перезапуска контейнера.

Кнопка «Остановить поиск» приостанавливает очередь и останавливает активные поиски в slskd. «Возобновить поиск» продолжит обработку оставшихся треков. Кнопка «Остановить и очистить всё» останавливает активные поиски и удаляет все записи очереди. Добавление нового списка также автоматически возобновляет остановленную очередь. Новые поиски отправляются в slskd параллельно, по мере освобождения заданных слотов. Настройки раскрываются рядом с очередью; панель сжимает основную область и не закрывает её.

Для каждого трека показывается время первого прохода и суммарное время поиска; сводные индикаторы складывают время по текущим записям, включая время активных поисков. Список можно добавить в режиме «Искать и скачивать» либо «Только поиск». Для найденных в режиме поиска файлов доступна кнопка «Скачать найденное». Статус «Скачано» выставляется после того, как slskd сообщит `Completed, Succeeded`.

Повторный проход начинается после окончания первичных поисков для списка, поэтому не занимает их слоты. Поисковая ошибка переводится на повторный проход независимо от настройки повтора совпадений без результата; если ошибка повторится, приложение запускает ещё одну попытку строго по одному треку за раз. Отсутствие подходящих совпадений само по себе не считается ошибкой и повторяется только при включённой настройке.

POST-запросы создания поиска и постановки скачивания сериализуются, а ответы HTTP 429 повторяются с учётом `Retry-After` и задержкой. Это соответствует ограничению slskd, при котором параллельные POST одного типа могут получить 429.

## Рекомендации Last.fm

Во вкладке «Рекомендации Last.fm» укажите API key и Shared Secret из [страницы API аккаунта Last.fm](https://www.last.fm/api/account), нажмите «Подключить Last.fm», подтвердите доступ в новой вкладке и вернитесь нажать «Я разрешил доступ · завершить». Используется desktop flow `auth.getToken` → подтверждение на Last.fm → `auth.getSession`; подпись `api_sig` формируется сервером MD5 из отсортированных параметров и Shared Secret. Секрет не возвращается интерфейсу.

Доступны четыре варианта персональных рекомендаций: похожие треки на ваши топ-треки за выбранный период; похожие треки на недавно прослушанные; похожие треки на отмеченные любимыми; популярные треки исполнителей, похожих на ваших топ-исполнителей. Также можно получить топ треков или исполнителей по тегу/жанру и похожих исполнителей или треки для введённой пары «исполнитель — трек». Last.fm предоставляет для этого отдельные методы чартов, похожих артистов и треков, а также теговые чарты; приложение объединяет ответы, удаляет дубликаты и позволяет добавить выбранное в очередь.

Рекомендации основаны на методах [`user.getTopTracks`](https://www.last.fm/api/show/user.getTopTracks), [`user.getRecentTracks`](https://www.last.fm/api/show/user.getRecentTracks), [`user.getLovedTracks`](https://www.last.fm/api/show/user.getLovedTracks), [`artist.getSimilar`](https://www.last.fm/api/show/artist.getSimilar), [`track.getSimilar`](https://www.last.fm/api/show/track.getSimilar) и [`tag.getTopTracks`](https://www.last.fm/api/show/tag.getTopTracks). Last.fm API просит использовать разумную частоту запросов, поэтому вызовы выполняются последовательно; рекомендации для категорий, кроме недавних прослушиваний, кэшируются на 10 минут. Для недавних прослушиваний при каждом обновлении приложение запрашивает 100 последних прослушиваний, случайно выбирает одно как затравку и получает до 100 похожих треков через `track.getSimilar`. После удаления дублей из них случайно выбирается заданное количество рекомендаций. Если Last.fm вернул меньше нужного числа, показываются все полученные рекомендации. Рекомендации можно запустить сразу или отложить в очередь и начать поиск позже кнопкой «Запустить отложенные».

### Плейлист рекомендаций в Navidrome

При запросе категории «Похожие на недавние прослушивания» результаты сразу сохраняются в SQLite. Их можно получить отдельно от очереди скачивания через `GET /api/lastfm/playlists/recent-tracks`; в ответе есть исходная информация рекомендации, состояние загрузки и `available`/`local_path`. У выбранных рекомендаций сохраняется связь с записью очереди, поэтому повторная отправка той же рекомендации не создаёт второй элемент.

После успешной загрузки soulseek-queue перемещает файл из завершённой папки slskd в `/srv/soulseek/playlists` на хосте. В `.env` задайте `SLSKD_DOWNLOADS_HOST_PATH` — хостовый путь к завершённым загрузкам slskd. Он должен быть одной и той же папкой, примонтированной в slskd как `/downloads` и в soulseek-queue как `/downloads`. В slskd укажите `SLSKD_DOWNLOADS_DIR=/downloads` (или `directories.downloads: /downloads`).

```yaml
services:
  slskd:
    volumes:
      - /srv/soulseek/downloads:/downloads
  soulseek-queue:
    volumes:
      - soulseek_queue_data:/data
      - /srv/soulseek/downloads:/downloads
      - /srv/soulseek/playlists:/playlists
```

В Navidrome примонтируйте ту же целевую папку как библиотеку, например `/srv/soulseek/playlists:/music:ro`, установите `MusicFolder=/music`, `PlaylistsPath=.` и включите `AutoImportPlaylists`. Для `soulseek-queue` в `.env` используются `DOWNLOAD_DESTINATION_PATH=/playlists`, `NAVIDROME_MUSIC_PATH=/playlists` и `NAVIDROME_PLAYLIST_PATH=/playlists`. Папка плейлистов должна быть доступна на запись очереди и на чтение Navidrome.

После статуса `Completed, Succeeded` приложение ищет готовый файл в смонтированной папке slskd и переносит только сам файл в `/playlists/Похожие на недавние прослушивания/<имя файла>`. Путь peer и вложенные каталоги Soulseek не сохраняются. Для скачиваний вне рекомендационного плейлиста используется `/playlists/Загрузки/<имя файла>`. При одинаковых именах добавляется суффикс, чтобы не затереть файл. Старые файлы, уже перенесённые во вложенные каталоги, постепенно перемещаются в целевую структуру фоновым монитором. M3U `Похожие на недавние прослушивания.m3u` хранится в корне MusicFolder, включает все аудиофайлы в папке плейлиста и содержит относительные ссылки в неё. Он обновляется сразу после успешного переноса файла.

Чтобы Navidrome сразу перечитал изменённый M3U и увидел трек в приложениях, задайте в `.env` `NAVIDROME_URL`, `NAVIDROME_USERNAME` и `NAVIDROME_PASSWORD`. Используйте пользователя Navidrome с правом запуска сканирования библиотеки. Очередь вызывает совместимый Subsonic API `startScan`; если сканирование уже идёт, она дождётся его завершения и запустит следующее. Без этих учётных данных M3U всё равно обновляется на диске, а Navidrome импортирует его при следующем сканировании библиотеки. Сам список рекомендаций и состояния ожидания доступны сразу через `GET /api/lastfm/playlists/recent-tracks`.

Чтобы направлять через Gluetun только API-запросы Last.fm, включите в нём `HTTPPROXY=on`, разрешите порт `8888` во входном firewall (`FIREWALL_INPUT_PORTS=8888`) и задайте приложению `LASTFM_PROXY_URL=http://gluetun:8888`. Оба контейнера должны быть подключены к одной Docker-сети; если Compose-проекты разные, подключите их к общей внешней сети. В этом варианте не задавайте приложению `network_mode`: его веб-порт остаётся на `8090`, а связь со slskd сохраняется.

Формат строки произвольный, обычно `Исполнитель — Название`. Сначала приложение отправляет `POST /api/v0/searches` с `searchText`, UUID, `searchTimeout` (миллисекунды) и лимитами. Оно опрашивает `GET /api/v0/searches/{id}` до завершения поиска, после чего читает список через `GET /api/v0/searches/{id}/responses`. В результате отображаются число ответивших пользователей, количество аудиофайлов, лучший процент совпадения и выбранный порог. Для первого и повторного прохода можно задать разные пороги: низкое значение находит больше вариантов, но может выбрать неверный файл. Загрузки ставятся массивом файлов `{filename, size}` через `POST /api/v0/transfers/downloads/{username}`. Для остановки поиска используется `PUT /api/v0/searches/{id}`.

Сверены поля поиска, получение результатов и постановка файла на скачивание с [описанием slskd API](https://slskd-api.readthedocs.io/en/latest/api.html); таймаут в миллисекундах дополнительно подтверждён практическим примером в [обсуждении slskd](https://github.com/slskd/slskd/issues/1820). API-ключ должен иметь права на чтение и изменение.
