# Треклист для slskd

Веб-приложение принимает по одному поисковому запросу на строку, выполняет ограниченное число поисков одновременно, выбирает аудиофайл из ответов Soulseek и ставит его в очередь загрузок slskd. Если первый поиск ничего подходящего не нашёл, приложение может повторить его с более длинным таймаутом.

## Запуск через Docker Compose

1. Скопируйте `.env.example` в `.env` и укажите адрес slskd и API-ключ.
2. Подключите сервис к той же Docker-сети, что и slskd. Если slskd работает отдельно, задайте доступный из контейнера адрес, например `http://host.docker.internal:5030`.
3. Запустите `docker compose up -d --build`.
4. Откройте `http://localhost:8080`.

В slskd создайте API-ключ с правами на поиск и управление загрузками. Порт API (обычно `5030`) должен быть доступен из контейнера. Можно также настроить URL и ключ в окне шестерёнки приложения; настройки хранятся в именованном Docker volume `soulseek_queue_data`.

## Настройки

- Длительность обычного поиска: 5–600 секунд.
- Одновременные поиски: 1–32.
- Минимальное сходство имени файла с названием трека: 10–90% (по умолчанию 25%).
- Повторный поиск ненайденных треков: включается отдельно, с длительностью 5–1800 секунд.

Таймаут `searchTimeout` передаётся slskd в миллисекундах. Для списка допускается до 500 строк за отправку; записи очереди сохраняются в SQLite и остаются после перезапуска контейнера.

Кнопка «Остановить поиск» приостанавливает очередь и останавливает активные поиски в slskd. «Возобновить поиск» продолжит обработку оставшихся треков.

Формат строки произвольный, обычно `Исполнитель — Название`. Сначала приложение отправляет `POST /api/v0/searches` с `searchText`, UUID, `searchTimeout` (миллисекунды) и лимитами. Оно опрашивает `GET /api/v0/searches/{id}` до завершения поиска, после чего читает список через `GET /api/v0/searches/{id}/responses`. Из результатов выбирается аудиофайл с наиболее похожим именем. Порог сходства настраивается: низкое значение находит больше вариантов, но может выбрать неверный файл. Загрузки ставятся массивом файлов `{filename, size}` через `POST /api/v0/transfers/downloads/{username}`. Для остановки поиска используется `PUT /api/v0/searches/{id}`.

Сверены поля поиска, получение результатов и постановка файла на скачивание с [описанием slskd API](https://slskd-api.readthedocs.io/en/latest/api.html); таймаут в миллисекундах дополнительно подтверждён практическим примером в [обсуждении slskd](https://github.com/slskd/slskd/issues/1820). API-ключ должен иметь права на чтение и изменение.
